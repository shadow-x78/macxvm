# MacXVM - ترحيل الآلة

هذه الصفحة تشرح ترحيل آلة افتراضية إلى مضيف آخر: فحص التوافق، الترحيل
الحقيقي، الإلغاء، والدوران. الترحيل يعمل مع مسارَي الكرت: `vfio` و`reims`.

**الميزة تجريبية.** لا يوجد بعدُ تعريف مكتمل، ولا نتيجة ترحيل على عتاد
حقيقي. حالة كل مهمة مسجلة في
[artifacts/mxgpu/execution-ledger.json](../artifacts/mxgpu/execution-ledger.json).

## الأوامر

```bash
macxvm migrate NAME --to USER@HOST --check    # تقرير للقراءة فقط
macxvm migrate NAME --to USER@HOST --live     # الترحيل الحقيقي
macxvm migrate NAME --cancel                  # إلغاء جلسة سارية
```

`--check` لا يوقف الآلة ولا يغيّر أي شيء. `--live` يعيد فحص التوافق كاملًا
داخل الأمر قبل أي إيقاف، ولا يعتمد على فحص قديم. `--cancel` يرفض العمل إذا
لم تكن هناك جلسة صالحة أو كانت الجلسة قديمة.

## ما الذي يفحصه الأمر

| الفحص | ما الذي يمنعه |
|---|---|
| طراز الكرت ومعرّف المجموعة الفرعية | وجهة فيها كرت آخر |
| إصدار البرنامج الثابت | زوج غير متوافق من البرنامج الثابت و`GSP` |
| إصدار التعريف | تعريف يختلف عن تعريف المصدر |
| نوع آلة QEMU | نوع آلة لا يدعمه المصدر |
| راية المعالج | معالج بلا الرايات المطلوبة |
| صورة OpenCore و`NVRAM` | وجهة لا تملك الصورة نفسها |
| عنوان الكرت في الوجهة | وجهة بلا عنوان للكرت |
| هوية جهاز USB | جهاز USB بلا هوية في الوجهة |

الحقل الفارغ في الوجهة ليس سببًا للرفض: غياب معلومة في الطرف الآخر لا يعني
اختلافًا. الفارق المؤكد فقط هو سبب الرفض.

## خطة الترحيل

الخطة تحفظ في `<vmdir>/migration/migration-plan.json` وتحتوي:

- هوية المصدر والوجهة.
- الطراز ومعرّف المجموعة الفرعية للكرت، وإصدار البرنامج الثابت والتعريف.
- خريطة الأجهزة: خانة الضيف في المصدر، وعنوان أو هوية الجهاز في الوجهة.
- خريطة الهوية: الرقم التسلسلي و`MLB` و`UUID` و`MAC`، وهي تبقى كما هي في
  الضيف حتى لا تتغير هوية الآلة.
- سلسلة الأقراص، وعقدة لكل قرص مع مسار الأساس وصيغته.
- حالة الشبكة والمنفذ الذي يُعاد توجيهه.

بصمة الخطة لا تعتمد على وقت توليدها، فتُعاد بنفس النتيجة بعد أي إعادة
فحص.

يرسل `--live` الخطة إلى الوجهة إلى جانب نقطة تفتيش الضيف، في مجلد الترحيل
الخاص بالوجهة:
`${MACXVM_HOME:-${XDG_DATA_HOME:-$HOME/.local/share}/macxvm}/vms/NAME/migration`.
يتبع هذا التعبير بيئة الوجهة، فتقرأ الوجهة الخطة من المكان نفسه الذي تحفظ
فيه خطتها. تقرأ الوجهة الخطة من مسار `--plan`، وترفض خطة لا تطابق جلسة
الترحيل.

## حالة الجلسة

| الحالة | المعنى |
|---|---|
| `prepared` | الخطة جاهزة ولم يبدأ شيء |
| `pre-copy` | نقل الأقراص قيد التنفيذ والمصدر يعمل |
| `source-stopped` | أُوقف المصدر بعد آخر كتابة |
| `final-state-sent` | أُرسلت الحالة النهائية |
| `destination-validated` | تحققت الوجهة من الاستعادة |
| `source-fenced` | فُصل المصدر رسميا |
| `committed` | كُتب سجل الالتزام، والوجهة هي المالك |
| `destination-active` | الوجهة هي المالك والجهاز يعمل |
| `cancelled` | أُلغيت الجلسة |
| `failed` | فشلت الجلسة |

الجلسة الملغاة أو الفاشلة أو الملتزمة لا تقبل الإلغاء. بعد كتابة سجل
الالتزام تصبح الوجهة هي المالك، ولا يوجد رجوع تلقائي إلى المصدر.

## التراجع

1. اقرأ `migration/session.json` وحالة الجلسة ولا تخمّن المالك.
2. إذا لم يكتب سجل الالتزام: أوقف الوجهة ولا تستأنف قرصها.
3. إذا كانت ملكية المصدر مؤكدة، استأنف المصدر إذا كان متوقفًا.
4. إذا كانت ملكية الوجهة أو حيويتها غير مؤكدة، أبقِ الطرفين متوقفين واطلب
   التسوية.
5. احذف الحالة المؤقتة بعد إثبات الفصل، وأعد الفحص قبل أي محاولة جديدة.

## ملكية الكرت أثناء الترحيل

الكرت الممرّر لا يمكن أن يكون في يد حالتين في الوقت نفسه. MacXVM يأخذ
قفلًا حصريًا على عناوين الكرت وعلى مجموعات `IOMMU` قبل تشغيل الجهاز، ويمرر
الملف إلى QEMU ليبقى القفل قائمًا حتى يخرج. الترحيل إلى مضيف آخر لا ينقل
القفل؛ الوجهة تأخذ قفلها الخاص بعد أن تتأكد أن المصدر لم يعد يملك الكرت.

## ما الذي لم يُختبر بعد

- الترحيل على عتاد حقيقي مع `vfio`.
- الترحيل على عتاد حقيقي مع `reims` في وضع المشاركة.
- استئناف القرص بعد الفشل في منتصف النقل.
- الترحيل بين مضيفين بنسخة تعريف مختلفة.
